# ReplyCount · 回复计数

Vencord 插件：在每条消息下面显示它**总共被回复了多少次**，点一下就能看到都有谁回复了、跳转过去。频道右上角有开关按钮。

- 消息下方出现「💬 3 条回复」的小标签，被回复过的消息才显示
- 点标签：列出所有回复（谁、说了什么、什么时候），点任意一条跳转过去
- 新回复实时 +1，回复被删实时 −1
- 频道右上角（置顶、子区、搜索那一排）的按钮：
  - **显示回复计数**：开关，关掉后标签全部隐藏
  - **补全当前频道的计数**：往后翻历史，把没加载过的回复也数进来
  - **清空已统计的数据**

## 安装

这是一个 Vencord **userplugin**，需要用源码版 Vencord 构建。

```bash
cd 你的Vencord目录/src/userplugins
git clone https://github.com/xma1Soap/vencord-reply-count replyCount
cd ../..
pnpm build
```

然后在 Discord 里按 `Ctrl+R` 刷新，到 设置 → Vencord → 插件 里启用 **ReplyCount**（会自动启用依赖的 MessageAccessoriesAPI），再 `Ctrl+R` 一次。

更新：在 `replyCount` 目录里 `git pull`，再 `pnpm build`、`Ctrl+R`。

## 计数是怎么来的

Discord 没有提供「这条消息被回复了几次」的接口，插件只能自己数：客户端收到的每一条消息（打开频道、往上翻历史、实时新消息）都会过一遍，是回复就记到被回复的那条消息名下。数据只存在内存里，重启 Discord 后重新统计。

所以计数有两种状态：

| 显示 | 含义 |
|---|---|
| `3 条回复` | 从这条消息到最新消息之间，所有消息都看过了，**这就是总数** |
| `3+ 条回复` | 这条消息之后有一段消息还没加载过（比如通过链接或搜索跳到很早的消息），实际可能更多 |

遇到 `+` 时，点右上角按钮 → **补全当前频道的计数**，或者点标签 → **补全这条消息的计数**。插件会从那里往后一页一页（每页 100 条）翻到最新，翻完后 `+` 就会消失。翻到一半停下（手动停止或到达页数上限）的话，下次补全会接着往后翻。

> 补全会以你的账号请求消息历史，和你自己往下翻聊天记录是同一个接口。插件每页之间会停一会儿，并限制单次最多翻多少页；热闹的频道里跳到很久以前的消息时，可能需要多补全几次。

## 设置

| 设置 | 默认 | 说明 |
|---|---|---|
| 显示回复计数 | 开 | 同右上角菜单里的开关 |
| 最少回复数 | 1 | 被回复至少这么多次才显示标签 |
| 显示右上角按钮 | 开 | 改动后需要 `Ctrl+R` |
| 扫描页数上限 | 30 | 补全时一次最多翻多少页（每页 100 条） |
| 扫描间隔 | 600 ms | 补全时每页之间等待多久，太快可能被 Discord 限流 |

## 说明

- 只统计「回复」（消息上方带引用条的那种），转发不算
- 只统计直接回复；回复的回复算在它直接回复的那条消息上
- 子区（thread）里的讨论不算回复
- 插件属于客户端修改，请自行评估风险
